## MFC作業時の行動規約（重要）

- **コードを提案・編集する前に、必ず該当の `.rc`（`prompt_editor.rc`）と `resource.h` を読むこと**。コントロールIDを推測で書かない
- ダイアログクラスを編集するときは、対応するヘッダ（メンバ変数とDDX定義）も併せて確認すること
- 新規のリソースID（`IDC_` / `IDD_` / `IDR_`）を勝手に発番せず、既存IDを使うこと。新規発番が必要な場合は理由とともに確認を求めること
- メッセージマップ（`BEGIN_MESSAGE_MAP`〜`END_MESSAGE_MAP`）は既存ブロックを確認してから追記し、マクロの省略・重複をしないこと
- ビルド構成・プロジェクト設定（プラットフォーム、文字セット、MFCリンク方式）を変更しないこと
- ビルドはClaudeが実行せず、VS2022側で行う前提とする（エラーが出たらテキストを貼って共有する運用）

## 実行時不具合（クラッシュ・誤動作）のデバッグ手順

- 実行時の不具合は、まずVS2022を中断させたデバッグ画面を提示する
- そこからClaude Codeが必要なデバッグ情報（呼び出し履歴・ローカル変数等）を要求してくるので、それに応じて提供する
- 呼び出し履歴（コールスタック）の取得：デバッグで中断した状態で `Ctrl+Alt+C` → ウィンドウ内で右クリック → 「すべてコピー」でテキストとして渡す
- コールスタックを正確に出すため、不具合追跡時は `Debug / x64` 構成でビルドすること（Release構成だと関数名が省略されることがある）

## MFCコーディング規約

- 文字列リテラルは `_T("...")` または `L"..."` で統一する。生の `"..."` は使わない
- DDX/DDVの向きに注意する
  - `UpdateData(TRUE)`：画面 → 変数（取得）
  - `UpdateData(FALSE)`：変数 → 画面（設定）
- リソースID命名規則を守る：`IDD_`（ダイアログ）／`IDC_`（コントロール）／`IDR_`（リソース）
- `new` した `CWnd` 派生オブジェクトの破棄責任・親子ウィンドウの所有権を明示的に管理する
- エラー処理の方針はプロジェクト内で統一する（MFC例外 `CException` 派生 / 標準例外のどちらかに寄せる）
- ファイル出力はUTF-8（BOMの有無は `MdGenerator` の既存実装に合わせる）
