# decisions.md — 設計判断の記録（ADR）

> **用途**：「なぜこの設計にしたか」を記録する。
> 後から見返したとき・Claudeが判断に迷ったときの根拠として参照する。

---

## 記録フォーマット

```
## ADR-XXX: タイトル
- **日付**：YYYY-MM-DD
- **状態**：提案中 / 採用 / 却下 / 廃止
- **背景**：なぜこの判断が必要だったか
- **決定内容**：何を選んだか
- **却下した選択肢**：何を選ばなかったか・理由
- **影響**：この決定による制約・副作用
```

## ADR-002: 使用量データの取得元

- **日付**：2026-07-02
- **状態**：採用
- **背景**：Claude Code の現在モデルと使用量をリアルタイムに取得する手段が必要だった
- **決定内容**：Claude Code がローカルに書き出すセッション記録
  `%USERPROFILE%\.claude\projects\**\*.jsonl` を1秒間隔で監視し、
  最終更新が最新のファイルを差分読み（追尾）して assistant 行の
  `"model"` と `"usage"`（input / output / cache_read / cache_creation トークン）を集計する
- **却下した選択肢**：
  - Anthropic API の呼び出し（APIキー管理と課金が発生し、"Claude Code の"使用量とは一致しない）
  - `claude` CLI のプロセス出力の解析（安定した機械可読出力がない）
- **影響**：JSONL のフォーマット変更に追従が必要。ファイルが無い環境では待機表示となる

## ADR-003: JSON解析方式

- **日付**：2026-07-02
- **状態**：採用
- **背景**：JSONL の解析に外部ライブラリ（nlohmann/json 等）を入れるか判断が必要だった
- **決定内容**：外部ライブラリは導入せず、キー文字列検索（`"model":"…"` / `"input_tokens":n`）
  による軽量抽出を自前実装する
- **却下した選択肢**：nlohmann/json 等の導入（必要なのは数キーの抽出のみで、
  依存追加・NuGet/vcpkg 管理のコストが見合わない）
- **影響**：JSONの厳密なパースは行わないため、キー名変更には文字列定数の修正で対応する

## ADR-004: UI構成と描画方式

- **日付**：2026-07-02
- **状態**：採用
- **背景**：「パルスメータのような」リアルタイム表示の実現方式を決める必要があった
- **決定内容**：ダイアログベースMFCアプリとし、パルスメータは `CStatic` 派生の
  自前描画コントロール（メモリDCによるダブルバッファ、心電図風スクロール波形）で実装。
  ダイアログ全体はダークテーマ（`WM_CTLCOLOR` で背景・文字色を制御）
- **却下した選択肢**：
  - `SS_OWNERDRAW` + `DrawItem`（`WM_PAINT` オーバーライドの方が全面制御しやすい）
  - グラフライブラリの導入（依存を増やさない方針のため）
- **影響**：描画は GDI のみ。リサイズ時は波形バッファを保持したまま再描画する

## ADR-005: ソース文字コードと .rc の扱い

- **日付**：2026-07-02
- **状態**：採用
- **背景**：日本語コメント・日本語UI文字列を安全に扱う必要があった
- **決定内容**：ソースは BOM なし UTF-8 とし、コンパイルオプションに `/utf-8` を付与。
  `.rc` ファイルは ASCII のみで記述し、日本語UI文字列は `OnInitDialog` でコードから設定する
- **却下した選択肢**：Shift-JIS ソース（Dev Container / Git 運用と相性が悪い）、
  `.rc` への日本語直書き（rc.exe は `/utf-8` 非対応で文字化けリスクがある）
- **影響**：UI文言の変更はリソースエディタではなくコード側で行う

## ADR-006: プラン使用制限（%表示）の取得方法

- **日付**：2026-07-02
- **状態**：採用（ADR-002 の「ネットワーク通信なし」を一部変更）
- **背景**：Claude Desktop の設定画面と同じ表示形式（セッション/週間の使用率バー＋
  リセット時刻）が要望された。使用率の分母（プラン上限）とリセット時刻は
  ローカルの JSONL には存在せず、サーバーからしか取得できない
- **決定内容**：Claude Code がログイン時に保存する OAuth アクセストークン
  （`%USERPROFILE%\.claude\.credentials.json`）を読み取り専用で利用し、
  使用量エンドポイント `GET https://api.anthropic.com/api/oauth/usage` のみを
  WinHTTP で60秒間隔・ワーカースレッドで呼び出す。応答の
  `five_hour` / `seven_day` / `seven_day_fable`（旧 `seven_day_opus`）各セクションの
  `utilization`（使用率%）と `resets_at`（リセット時刻）を表示する
- **却下した選択肢**：
  - ローカルJSONLからの使用率の推定（プラン上限を持たないため数値がでたらめになる）
  - APIキーによる Usage API 利用（Claude Code のサブスクリプション使用量とは別物）
  - トークンのリフレッシュ処理の自作（OAuthクライアント情報が必要で複雑。
    期限切れ時は「Claude Code を起動して更新」を促す表示で対応）
- **影響**：この1エンドポイントに限りネットワーク通信を行う（メッセージ送信等は
  引き続き行わない）。トークン未保存・期限切れ・オフライン時は使用量セクションのみ
  エラー表示とし、パルスメータ等のローカル機能は影響を受けない。
  応答キー名の変更（モデル世代交代）には候補キーの追加で追従する
